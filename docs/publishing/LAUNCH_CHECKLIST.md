## 0b. How to publish on the App Store — the Apple account is verified (written 2026-09-28, PUB-12, for a stakeholder with an iPhone and no Mac; rewritten 2026-10-09, MM-12: the team builds, uploads and submits from CI)

**Who does what.** On 2026-10-09 you asked for the App Store work to be automated ("1-ci variant, avtomatik et"). From then on **the team does everything App Store Connect lets a program do**: the build, the TestFlight upload, the listing texts, the screenshots, the age rating, the categories, the price and countries, choosing the build and **submitting it for review**. The team starts each of these with a commit of `tower-clash/release/ios-release.request` or `tower-clash/release/ios-store.request` (`docs/MOBILE.md` §3.2) — but only **after you write "iOS sirləri hazırdır" in the chat**. Without your secrets nothing can run; and nothing becomes public until your own click in step 10. The steps below are **only yours**: a browser is enough (developer.apple.com, appstoreconnect.apple.com, admob.google.com, github.com), no Mac. Steps 1–9 are **one-time**; step 10 repeats **per version**. Texts to paste come from **`APP_STORE_CONNECT_SHEET.md`** (the "sheet"). Version 1.0.0 goes out **without in-app purchases** (sheet variant B); the build sent to App Review is **1.0.0 (8)**, the first one with your real AdMob ids.

0. **GitHub Pages (one-time, 1 minute — added 2026-10-09, BUG-26).** The privacy policy URL that Apple and Google require (`https://pervincinal.github.io/InsiderTest/privacy.html`) is not live yet. GitHub → https://github.com/pervincinal/InsiderTest/settings/pages → *Build and deployment* → *Source*: **GitHub Actions** → it saves by itself. **Then the second half (found 2026-10-09 after Pages was switched on):** enabling Pages creates a protected `github-pages` environment that lets only `main` deploy, and our deploys come from the working branch — https://github.com/pervincinal/InsiderTest/settings/environments → **github-pages** → *Deployment branches and tags* → **Add deployment branch or tag rule** → *Name pattern* `claude/tower-war-game-plan-weqwpb` → **Add rule**. Write "Pages açıldı" in the chat; the team's next push deploys and checks it (`scripts/ciStatus.mjs` shows the Pages job).
1. **Team ID (one-time).** https://developer.apple.com/account → *Membership details* → copy the 10-character **Team ID** (e.g. `AB12CD34EF`). Keep it for step 4.
2. **Register the bundle id (one-time).** developer.apple.com/account → *Certificates, Identifiers & Profiles* → *Identifiers* → "+" → **App IDs** → Continue → type **App** → Continue → *Description* `Tower Clash`; *Bundle ID* **Explicit** `com.pervincinal.towerclash`; *Capabilities*: leave the defaults, make sure **In-App Purchase** is ticked (it is on by default; harmless in 1.0.0, needed in 1.0.1) → Continue → **Register**. Nothing else (no Game Center, no Push).
3. **App Store Connect API key (one-time).** https://appstoreconnect.apple.com → *Users and Access* → *Integrations* tab → *App Store Connect API* → **Team Keys** → "+" (Generate API Key) → *Name* `GitHub CI`; *Access* **Admin** (needed once so the CI can create the distribution certificate and profile; can be downgraded to *App Manager* after the first successful upload) → **Generate**. On the page note the **Issuer ID** (top, a UUID) and the new row's **Key ID** (10 characters), then **Download API Key** → `AuthKey_<KEYID>.p8`. **The file can be downloaded only once** — if lost, revoke the key and make a new one. Do not send the file anywhere except step 4.
4. **Four GitHub secrets (one-time).** https://github.com/pervincinal/InsiderTest → *Settings* → *Secrets and variables* → *Actions* → **New repository secret**, four times, names exactly: `APPLE_TEAM_ID` = the Team ID of step 1; `APP_STORE_CONNECT_API_KEY_ID` = the Key ID; `APP_STORE_CONNECT_API_ISSUER_ID` = the Issuer ID; `APP_STORE_CONNECT_API_KEY_P8` = the **whole text** of the `.p8` file opened in a text editor, including the `-----BEGIN PRIVATE KEY-----` and `-----END PRIVATE KEY-----` lines (on the iPhone: open the file in Files → share → copy; on a PC: Notepad). The team never sees the values, only whether a run passes.
5. **Create the app record (one-time) — done 2026-10-09 as `Tower Clash: Tap & Conquer`** (`Tower Clash` was taken; sheet §1; the home-screen label stays `Tower Clash`). For the record: App Store Connect → *My Apps* → "+" → **New App**: *Platforms* iOS; *Name* `Tower Clash: Tap & Conquer`; *Primary Language* English (U.S.); *Bundle ID* the one from step 2; *SKU* `towerclash`; *User Access* Full Access → **Create**. Apple's API cannot create this record, so it is yours.
6. **AdMob iOS ids (one-time).** §0c steps 1–5 below: three more secrets `ADMOB_IOS_APP_ID`, `ADMOB_IOS_INTERSTITIAL`, `ADMOB_IOS_REWARDED`. Without them the review build would show Google's "Test Ad" placeholders.
7. **Review contact — four secrets (one-time).** Same GitHub page as step 4, **New repository secret** four times: `ASC_REVIEW_FIRST_NAME` = your first name; `ASC_REVIEW_LAST_NAME` = your last name (as on the developer account — the same name is used for the copyright line `© 2026 <first> <last>`; if the account belongs to a company, write the company name in the chat instead); `ASC_REVIEW_PHONE` = your phone with `+` and the country code (e.g. `+994 50 123 45 67`); `ASC_REVIEW_EMAIL` = a mailbox you read every day during the review. Apple shows them only to its reviewers; they never go into the repository.
8. **App Privacy (one-time).** App Store Connect → *My Apps* → Tower Clash: Tap & Conquer → left menu **App Privacy** → *Get Started* → tick the data types and answers of **sheet §4** (variant B: *Purchase History* is **not** ticked) → last screen *Tracking*: **No** → **Publish**. Apple does not accept these answers from an API key, so this form is yours.
9. **Contact e-mail, then the go-ahead (one-time).** Write in the chat the e-mail address (and the name / address line) to show on the privacy and support pages, where `[developer e-mail]` / `[developer name / address]` still stand (§0 step 3) — the team publishes the pages; Apple rejects an app whose privacy page has no contact. When steps 1–8 are done, write **"iOS sirləri hazırdır"** in the chat.
10. **Release (per version).** Apple's answer arrives at the e-mail of step 7, usually in 1–3 days. When App Store Connect → Tower Clash: Tap & Conquer → *App Store* shows **Pending Developer Release**, press **Release This Version**. Nothing becomes public before this click (the team always submits with "Manually release this version").

**What the team then does by itself** (via the request files; progress in the daily report): build **1.0.0 (8)** with your AdMob ids and upload it to TestFlight → upload the listing texts (sheet variant B), the ten iPhone screenshots, the age rating (9+), the categories (Games › Strategy, Casual), the price **Free** and the countries **Azerbaijan, Türkiye, Kazakhstan, Georgia** (`POST_LAUNCH.md` §2.2), the TestFlight group **Team** → choose build 8, answer export compliance and content rights → **submit for review**. A rejection is answered by the team in the report thread (the text is written for you to paste in the Resolution Center). If App Store Connect refuses the automatic price / country setting, the team asks you for that one screen (sheet §3) in the report. *Optional, not needed for the release:* to try a build on your iPhone, App Store Connect → TestFlight → *Internal Testing* → **Team** → "+" → add yourself, then install the free **TestFlight** app.

## 0c. AdMob account and ad ids — "AdMob hesabı və reklam ID-ləri" (written 2026-10-02, PUB-13, for a stakeholder with an iPhone and a browser)

Without these ids every store build shows **Google's test ads** ("Test Ad" label, no revenue): when the secrets are empty, `tower-clash-ios-release.yml` keeps Google's test app id in `Info.plist` and the build uses Google's test units (`ADMOB_TEST_UNITS` in `src/economy/providers/config.ts`); on the `appstore` lane the job only prints a warning. That is fine on TestFlight and **not** fine on the public App Store (§0b step 6). Everything happens in a browser (admob.google.com, github.com; a computer is easier, Safari on the iPhone also works). Free, ≈ 30 min. Steps 1–8 and 11 are **one-time**; step 9 repeats only when an id changes; step 10 is the rule for TestFlight with real ads. This section closes **MZ7** (iOS half: steps 1–5; Android half: step 6) and **MZ8** (step 7). **MZ12** stays open until the W7 decision (step 8).

What the code needs, and nothing more: **one Interstitial unit** (placement `int_level_break`, the only interstitial in `AD_PLACEMENTS`, `src/economy/catalog.ts`) and **one Rewarded unit** shared by the four rewarded placements `rv_double_gold`, `rv_continue`, `rv_free_booster`, `rv_daily_chest` (`rewardedByPlacement` in `capacitor.config.ts` is empty, so all four use the single `rewarded` id). No banner, app-open or native units.

1. **Sign in (one-time).** https://admob.google.com → *Get started* → sign in with a Google account (the one for the future Play Console is fine) → country, time zone, payment currency (USD) → accept the AdMob terms → *Create AdMob account*. Payment details and the address PIN come later (`ACCOUNTS.md` §5.4 step 7) and are not needed for the ids. The account may show "getting ready" / "under review" for a few days; ids can be created meanwhile.
2. **Add the iOS app (one-time).** Left menu *Apps* → **Add app** → platform **iOS** → "Is the app listed on a supported app store?" **No** (it is not live yet) → *App name* `Tower Clash` → **Add app**. The confirmation page shows the **App ID** `ca-app-pub-<16 digits>~<10 digits>` — with a **tilde `~`**. Copy it (it stays under *Apps* → Tower Clash (iOS) → *App settings*).
3. **Two ad units (one-time).** On that page *Create ad unit* (or *Apps* → Tower Clash (iOS) → *Ad units* → **Add ad unit**): (a) **Interstitial** → *Ad unit name* `tower_clash_ios_interstitial` → advanced settings untouched → **Create ad unit** → copy the **ad unit ID** `ca-app-pub-<16 digits>/<10 digits>` — with a **slash `/`** → *Done*. (b) **Add ad unit** → **Rewarded** → name `tower_clash_ios_rewarded` → reward amount `1`, reward item `Reward` (the game decides the reward itself and ignores this value — `admob.ts` only listens for the "rewarded" event); server-side verification off → **Create ad unit** → copy the ID → *Done*.
4. **Content settings (one-time).** The code already sends *max ad content rating G* and *not child-directed* on every start (`maxAdContentRating: General`, `tagForChildDirectedTreatment: false` in `src/economy/providers/admob.ts`); set the same in the console so it matches MZ7: *Blocking controls* → *All apps* → *Content* → **Maximum ad content rating: G** → Save. If AdMob asks whether the app is directed at children: **No**.
5. **Three GitHub secrets (one-time).** https://github.com/pervincinal/InsiderTest → *Settings* → *Secrets and variables* → *Actions* → **New repository secret**, three times, names exactly: `ADMOB_IOS_APP_ID` = the App ID of step 2 (`~`); `ADMOB_IOS_INTERSTITIAL` = the ID of step 3a (`/`); `ADMOB_IOS_REWARDED` = the ID of step 3b (`/`). No spaces, no quotes. An ad unit id in `ADMOB_IOS_APP_ID` would crash the app at start, so the release job stops with an error when that value has no `~` (the run fails instead of shipping); an App ID in one of the two ad-unit secrets is not checked — it does not crash, but no ad ever loads, so make sure both contain a `/`. Then write "AdMob iOS secrets added" in the report thread.
6. **Android (later, same clicks).** When the Play app record exists (G2): *Apps* → **Add app** → **Android** → not listed → `Tower Clash` → App ID → secret `ADMOB_ANDROID_APP_ID`; ad units `tower_clash_android_interstitial` → `ADMOB_ANDROID_INTERSTITIAL` and `tower_clash_android_rewarded` → `ADMOB_ANDROID_REWARDED`; then add the Android app to both messages of step 7. The Android release job (G5) reads them; nothing changes for iOS.
7. **Privacy & messaging (one-time, MZ8).** Left menu *Privacy & messaging*: (a) **European regulations** (GDPR: EEA, UK, Switzerland) → *Create message* → *Apps*: Tower Clash (iOS) → *Privacy policy URL* `https://pervincinal.github.io/InsiderTest/privacy.html` → language English (add others if offered) → user choices: keep **Consent** and **Manage options**, add **Do not consent** if offered → ad partners: Google's default list → **Publish**. (b) **US state regulations** → *Create message* → same app, same privacy URL → **Publish**. (c) **Do not** create the **IDFA explainer** (iOS tracking) message: the game never shows Apple's tracking prompt (MZ9 option A), so that message would never appear and would contradict App Privacy "Tracking: No". What the game does with them (`src/economy/providers/admob.ts`): at start `requestConsentInfo()`; where Google says consent is required (EEA/UK/CH) and the form exists, `showConsentForm()` once, before any ad loads; **Settings → Privacy options** appears only when UMP reports the options as `REQUIRED` and reopens the form with `showPrivacyOptionsForm()` — for players in the regulated US states this is where the US-state message opens. iOS always asks for non-personalised ads whatever the answer. Without a published message the form never shows, the Settings entry stays hidden and ads still run non-personalised (the code tolerates it), so this does not block TestFlight — publish before the public release.
8. **app-ads.txt (MZ12 — not blocking App Review).** AdMob → *Settings* → *Account information* → **Publisher ID** `pub-<16 digits>`. The team's file `docs/publishing/app-ads.txt.example` needs that id and must be served at the **root** of the developer website (`https://<domain>/app-ads.txt`); `https://pervincinal.github.io/InsiderTest/` is a sub-path and is never crawled, so it waits for the **W7** decision (a user-site repository `pervincinal.github.io`, or a custom domain). Write the choice and the publisher id in the report thread; the team prepares the file. Ads serve without it (some buyers skip the app, lower fill); Apple does not check it.
9. **Rebuild with the real ids (team; per id change).** Nothing to click: once the three secrets exist and you have written "iOS sirləri hazırdır" (§0b step 9), the team starts the build by committing `tower-clash/release/ios-release.request` (MM-12, `docs/MOBILE.md` §3.2 — the *Run workflow* button and the GitHub API are both unavailable to the team, so a commit is the only trigger). The run log shows `VITE_ADMOB_IOS_INTERSTITIAL: set`, `VITE_ADMOB_IOS_REWARDED: set` and the `plutil` step writing `GADApplicationIdentifier`; the team reports the result in the daily report. To install it on your iPhone (optional): the TestFlight note at the end of §0b.
   - **Build numbers (policy, Producer 2026-10-03):** build **7** is the current release candidate — no AdMob ids, so Google test ads; TestFlight only. The first build with the real AdMob ids is **build 8**, still version **1.0.0**: when the three secrets exist (§0b step 6), the Producer raises `config.buildNumber` to 8 and runs `npm run version:sync`, then the team commits the request file; **1.0.0 (8)** is the build the team submits to App Review (`tower-clash/release/ios-store.request`, `action=submit`, `build=8` — §0b, "What the team then does"). **1.0.1 with in-app purchases is build 9** (§0d step 7). Apple accepts each build number only once per version, so build 7 is never re-uploaded with the real ids.
10. **TestFlight with real ads.** From that build on the iPhone shows **real ads** (no "Test Ad" label) once AdMob serves the account — new accounts and apps not yet linked to a store often get few or no ads for the first days; then the interstitial simply does not appear and the rewarded buttons stay hidden (the game hides them when no ad is loaded) — that is not a bug. **Never tap your own ads** and do not replay rewarded videos to "test" — AdMob treats that as invalid traffic and can suspend the account. If AdMob asks to register a test device (*Settings* → *Test devices* → *Add test device* → iOS), it wants the device's advertising ID, which this game never reads (no tracking prompt); if you cannot obtain it, skip the registration and just do not tap ads — the ad flow itself was verified with Google's test ads.
11. **After the App Store release (one-time).** AdMob → *Apps* → Tower Clash (iOS) → *App settings* → *App store details* → **Add** → search "Tower Clash: Tap & Conquer" (the App Store name; another app already uses "Tower Clash") → select → Save. AdMob then reviews the app ("app readiness"); full serving starts after that. Same for Android after the Play release (there the name is `Tower Clash`).
