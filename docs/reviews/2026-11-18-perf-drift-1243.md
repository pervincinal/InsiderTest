# Perf-gate drift check on headless shell 1243 (PERF-14, 2026-11-18, tech-artist)

## Question
The `container` entry of `tower-clash/e2e/perf.baseline.json` came from headless shell **1194** (e3a9796, 2026-11-02: calib 17.93 ms, level 50 1.0843, title 0.2401, shop 1.0965). Since 2026-11-13 (ENV-1) the sandbox runs **1243** (`chromium_headless_shell-1243/chrome-headless-shell-linux64`). Does the stored entry still fit? The `ci` entry is out of scope, because CI installs its own Chromium 1134.

**Decision rule.** The baseline stands (nothing is written) if every scene's median norm on 1243 is within ×0.85–×1.15 of the stored container value. It is re-written with `perf:baseline --runs 5 --host container` only if a scene drifts outside that band in **both** dry runs. Even then, the rewrite happens only after a pre-2026-11-13 build (e.g. `git archive 1b304e5`) shows the drift is the browser and not the game. A game regression gets a new PERF item instead of a rewrite.

## Reading
- **1243 is about 18 % faster on this host, and the norm cancels that out.** The calibration loop went from 17.93 to 14.78 ms (×0.82). Frame work went ×0.82 on level 50 (19.66 → 16.06 ms), ×0.83 on shop (19.96 → 16.63 ms) and ×0.90 on title (4.29 → 3.87 ms). Because the calibration and the frames sped up by about the same factor, the norm barely moves. That is the purpose of the relative gate.
- **Title is the scene closest to the edge** (×1.07 in run 1, ×1.12 in the gate's single sample). Its absolute work is tiny (about 4 ms, mostly fixed raster and compositing of the layered idle title). Those fixed costs did not speed up as much as the JS calibration loop did, so a small upward shift in title's norm is what a browser change would produce. The spread of the 1243 samples (0.223–0.273) overlaps the stored 1194 spread (0.221–0.253). Title remains 0.08 below the ×1.2 warn line.
- Run 1's 4th repetition reads low in all three scenes at once (0.93 / 0.22 / 0.94). That is a fast moment on the host, not a scene effect, and the median ignores it.
- No scene came near ×0.85 or ×1.15 in the clean run, so I did not build the pre-1243 comparison (`1b304e5`). There is no drift to attribute to either the browser or the game.

## Decision
**The baseline stands.** Every scene's median norm on 1243 is within ×0.85–×1.15 of the stored container value: ×0.99 / ×1.07 / ×1.03, with the gate's own run at ×1.04 / ×1.12 / ×1.04. A rewrite needs drift outside the band in both runs, and run 1 already rules that out, so the missing quiet second run cannot change the outcome. `e2e/perf.baseline.json` is not written. No src/ change.

Follow-up worth one line: title's gate ratio of ×1.12 in a single sample leaves about 0.08 of headroom to the warn line on 1243. If CI or a later container run starts warning on title alone, re-measure the container entry before treating it as a regression.
