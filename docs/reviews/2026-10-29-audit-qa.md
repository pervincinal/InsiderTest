### 1.3 Performance (performance-optimization method)

Target: 60 fps = **16.67 ms** per frame; the stakeholder's iPhone 17 Pro Max is a 120 Hz panel (8.33 ms). `e2e/perf.spec.ts` itself writes "33 ms (30 fps) is the target on a real device", and its gate is **50 ms of main-thread work per frame (20 fps)**.

| Sample (headless shell, software raster, thread-CPU per frame) | CI (last run, given) | This container (2026-10-29, calib 17.8 ms, ratio 0.89, factor 1.00) | Script part (local) |
|---|---|---|---|
| Title idle 3 s | **17.6 ms** | **36.1 ms** (wall median 50 ms) | 1.8 ms |
| Level 50 seed 1 ×5 autoplay (8–36 units) | 14.3 ms | 20.9 ms (wall median 33.3, p95 66.7, max 116.6) | 3.3 ms |
| Shop 3 s | 15.5 ms | 22.1 ms | 1.5 ms |
| Level 40 ground build (×4 CPU, `?tilt`) | — | camera median 65.2 ms, flat 24.9 ms (one-off per level) | — |

Reading (CPU vs GPU triage):
- Script is 1.5–3.3 ms of each frame (≈ 8–16 %). The rest is the canvas raster and commit. On a phone that work moves to WebKit's canvas or GPU path, which **cannot be measured here**. The bottleneck on the target hardware is therefore unknown. M3-5 and MM-4 have been open since September, and the PERF-4 sprite-cache A/B (`?spritecache=0`) was never run on a device.
- The CI samples already sit at 86–106 % of a 16.67 ms frame on CPU raster alone. The 50 ms gate leaves 2.8–3.5× headroom, so a 2.5× regression passes CI (AUD-Q8).
- The **idle title is the most expensive frame in the game** on both hosts, and the most variable: 26.0 / 27.6 / 47–52 / 39.0 / 36.1 ms across containers (BUG-55 history plus today). Today this host calibrated 11 % *faster* than CI and still read the title at 2× CI (AUD-Q11).
- Bundle: 81.3 / 82 kB gzip eager. Lazy chunks: `lazyScreens` 22.7 kB gz, `ai` 8.1, `skinShapes` 7.4, locales az/ru/tr 5.0–6.0 each, `share` 3.9, `hudOverlays` 3.3. Inside the native shells the bundle is local, so the budget matters for the web/PWA first load only. 0.7 kB of headroom means the next feature bumps the budget again (80 → 88 → 92 → 82 so far).
- No heap or long-session measurement exists anywhere (AUD-Q12). Load time is not measured in CI.
- Forcing questions: *"Frame rate in the heaviest scene on the lowest-spec target device?"* Unknown, never measured. *"30 minutes without restarting, does memory grow?"* Unknown, never measured.

### 1.4 Saves (save-systems)

**What is serialized.** One JSON object under `towerclash.save.v3` (`src/ui/save.ts`). It holds `version`, `stars` (level → 0..3), `gold`, `crystals`, `entitlements`, `upgrades`, `skins` (owned and equipped), `charges`, `daily` (login streak), `challenge` (Daily: last win, streak, best, newest 30 days, paid milestones), `weekly` (best, newest 12 Mondays), `adCounters`, `purchases` (transaction ids plus `owned:` markers), `milestones`, `replayGold`, `defeats`, `skips`, `achievements`, `reviewAsked` and `settings` (colour-blind, sound, reduced motion, language, tones). A full 50-level player is **1,960 bytes**, so quota is not a practical concern. `purchases` grows by one id per consumable purchase and is unbounded but tiny. In-match state is not saved; a backgrounded match pauses (`visibilitychange`), and a killed match is lost by design.

**Versioning and migration.** v1 (`towerclash.save.v1`, no `version`, `coins`) and v2 (`.v2`, `coins`) are read once when v3 is absent, normalized and written under v3; the legacy keys are left in place. Browser probe: v1 → 5 stars, 60 gold; v2 → 14 stars, 230 gold; legacy keys kept. Additive fields arrive without a bump and are guarded by `tests/ui/saveUpgrade.test.ts` (build-7 fixture, `KNOWN_KEYS`, byte-stable round trip). There is **no newer-version guard**: `version` is never read on load (AUD-Q3).

**Atomicity.** Every change calls `writeSave`, which issues one `setItem` of the whole JSON. Per-key `setItem` is atomic in the engines, so a torn half-write is not the realistic failure, and Chromium showed the write synchronously at the result screen. What is missing: (a) a last-good copy (`.bak`), (b) any signal when the write fails, and (c) knowledge of WebKit's persistence window. WKWebView hands localStorage to a separate storage process that flushes it to disk later, so a force-quit or jetsam kill right after a win may lose that win. No test or TF check covers that (AUD-Q4).

**Corruption handling (probe, real game).** Each row seeds localStorage, boots, and reads the debug surface and storage.

| Seeded | Boots? | Stars / gold / noAds after boot | What localStorage holds afterwards | Notice to player |
|---|---|---|---|---|

Ten hostile boots and the quota run produced 0 page errors and 0 console errors. The game never crashes on a bad save. It loses the save silently.

**What a reinstall loses.** Everything: stars, gold, crystals, upgrades, crystal-bought skins, booster charges, all streaks and bests, achievements, settings and language. The in-game About card says so ("Progress is stored on this device"). In 1.0.1 RevenueCat `restore()` brings back non-consumables only (remove-ads, bundles and their skins); crystal packs do not come back. `reviewAsked` resets, so the rating prompt may be asked again after a reinstall. Backup restore is unverified on both platforms: Android has `android:allowBackup="true"` (Auto Backup may include the WebView's data directory), and on iOS the WKWebView data under `Library/` may be in iCloud device backups. `@capacitor/preferences` is not installed, so there is no native-backed copy (AUD-Q4).

## 3. Coverage gaps: what no test or guard covers today, ranked by risk

1. **Any run on a real phone.** WKWebView boot, touch, safe areas, audio unlock, background behaviour, memory pressure, frame time and heat (AUD-Q1). Every bug found on a device so far (BUG-33/34/35/39, RELAY-1) had been invisible to CI.
2. **The WebKit engine at all.** No Playwright WebKit project, and the simulator build is never launched (AUD-Q5). Text metrics, canvas filters and pointer events go unverified on the shipping engine.
3. **Save recovery.** The corrupt-save path is tested, but the test asserts the loss (AUD-Q2). There is no newer-version test (AUD-Q3), no failed-write UX test (AUD-Q10), and no e2e that boots the real game with a hostile save; this audit's probe is the first.
4. **Native persistence lifecycle.** App update over an installed save, reinstall, backup/restore, OS storage reclaim, and a kill right after a result (AUD-Q4). TF-28's reset removes the one natural real-world upgrade test.
5. **Device performance.** Frame time on device, 120 Hz, a 30-minute thermal/battery run, a low-end Android phone, and a relative regression gate in CI (AUD-Q8).
6. **Memory over a long session** (AUD-Q12).
7. **Touch-target size and minimum text size.** No guards, and the existing "44 px" checks are design px (AUD-Q6, AUD-Q7).
8. **Boot / first-paint time.** Not measured in CI; only TF-01 by hand.
9. **The native origin / scheme pin** (AUD-Q14).
10. **Naive-line progression past level 16.** 23 / 27 / 32 are informational and not gated (AUD-Q13).
11. **Audio interruptions and ad audio overlap** (AUD-Q19).
12. **The release build without the debug surface** (AUD-Q18), and e2e screenshot hygiene (AUD-Q15).
13. **Accessibility.** The UI is canvas-only, with no VoiceOver labels or Dynamic Type response. No test exists, and none is planned in the TF plan.

## 5. Five things that are good (measured, not praised)

1. **Hostile input never crashes the game.** In 14 probe scenarios (corrupt, empty, `null`, wrong types, v1, v2, v4, quota, SecurityError) the game reached the title with 0 page errors and 0 console errors. `normalizeSave` clamps every number (no NaN, Infinity or negatives; prototype-pollution keys are inert per `saveHostile.test.ts`). The v1 → v3 and v2 → v3 migrations work in the real browser and keep the legacy keys.
2. **The schema has a contract.** `tests/ui/saveUpgrade.test.ts` freezes a full build-7 save (all 50 levels, streaks, purchases, skins) and requires a byte-identical round trip. `KNOWN_KEYS` forces an explicit "default or migration" decision for any new field.
3. **Gates are deterministic and broad.** 1,725 unit tests are green; CI gates the reference player on all 50 levels, 90 days of Daily, 26 weeks of Weekly, 5 twists × 42 levels, and the naive human line on levels 1–16 in both tie orders. The smoke path (title → map → level 1 → win → result → unlock → pause) passed 4/4 today. Every entry in the BACKLOG Bugs section (BUG-1 … BUG-57, RELAY-1) is closed; the code bugs among them carry a regression test.
4. **The perf measurement is honest about its host.** It measures thread-CPU work per frame (BUG-47) with a calibration page (BUG-55), so a loaded or slow container cannot pass or fail the gate by accident. The bundle guard rejects native store and ad SDKs in the eager chunk and holds it at 81.3 / 82 kB through six lazy-chunk splits (PERF-5…10).
5. **Progress is written at every event, and purchases are idempotent.** Each star, gold, charge or purchase change persists immediately; `visibilitychange` pauses the sim and suspends audio, so backgrounding never loses a match. `grantProduct` refuses duplicate transaction ids and `owned:` markers, so a retry or restore can never double-grant.
